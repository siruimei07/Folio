# Folio 产品简介（Product Brief）

> **状态**：v0.3，已确认 · **更新**：2026-09-27（第一版界面改为英文；课程加上课程编号；按设计定稿更新界面结构）· **决策人**：Sirui · **整理**：Claude Code（依据 2026-09-26 的对话）；v0.3 由 Cowork 依据 2026-09-27 的设计对话修改
>
> 本文是 Folio 的产品依据：做什么、为谁做、第一版做到哪里。技术选型写在 `docs/adr/`，界面设计规格写在 `docs/design/handoff/`，两者都以本文为准；如有冲突，先改本文。

## 1. 一句话定位

**Folio 是一款 Windows 桌面资料库：按「学期 → 课程」整理学习资料，用标签区分笔记、课件、作业，支持快速搜索和应用内预览；每次改动都有记录，并同步到放在 iCloud 里的「云端仓库」文件夹，作为带历史的备份，也能在 iPhone、iPad 等设备上查看。**

它要比 Windows 自带的资源管理器更直观、更好看；版本管理像一个「只有一条主线的 Git」，但对日常资料足够简单。

## 2. 要解决的问题

1. **找文件慢**：按课程找文件要一层层点开；资源管理器没有标签。
2. **预览弱**：系统预览看不了渲染后的 Markdown 和高亮代码，PPT 预览依赖本机装了 Office。
3. **备份与多设备**：资料需要可靠的云端备份，也想在 iPhone、iPad 上查看；网盘只同步「现在的样子」，看不出什么时候改了什么。
4. **旧版本难找回**：笔记、代码、Word 报告需要找回旧版本；但 Git 对日常资料太重（分支、命令行、二进制文件让仓库膨胀）。

## 3. 用户与范围

| 项 | 决定 |
|---|---|
| 主要用户 | Sirui 本人：学生，在 Windows 电脑上管理资料，用 iCloud 做云端备份 |
| 次要用户 | 少数使用 Windows 的同学朋友：需要像样的安装包、自动更新和首次使用引导 |
| 平台 | Windows 10 / 11 桌面端。macOS 暂不考虑；以后需要时用 Swift 单独开发 Mac 版（2026-09-26 决定） |
| 界面语言 | 第一版只做英文界面，日期和时间用英文格式（`Sep 27`、`5:05 PM`）；界面文字全部外置，简体中文界面放到以后的版本（2026-09-27 决定）。中文文件名和文件内容照常显示、照常能搜 |
| 暂不考虑 | macOS 版、公开上架、团队协作 / 共享资料库、手机和平板 App |

## 4. 核心概念

| 概念 | 含义 |
|---|---|
| **资料库**（Library） | 本机上的一个普通文件夹，Folio 管理的文件都在里面，每台电脑各有一份。离开 Folio，它依然是一个结构清楚的文件夹。 |
| **学期**（Semester） | 资料库下的第一级文件夹，例如 `2026 秋`。第一级也可以是非学期的分组，例如 `个人`、`竞赛`。 |
| **课程**（Course） | 学期下的第二级文件夹，例如 `线性代数`、`Calculus of Several Variables`。每门课有颜色、缩写和课程编号（可选，例如 `MAT232`）：界面上显示为彩色方块，后面先写课程编号（加粗）、再写灰色的课程名；路径和提交说明里也用课程编号，方便快速辨认。课程里可以再建子文件夹（例如一个代码作业项目）。 |
| **标签**（Tag） | 贴在文件或文件夹上的类别，预设 `Notes`（笔记）、`Slides`（课件）、`Homework`（作业）、`Exams`（考试）、`Reference`（资料），可自定义名称、颜色和顺序。一个文件可以有多个标签。标签不改变文件在磁盘上的位置。 |
| **云端仓库**（Cloud remote） | 另一个文件夹，建议放在 iCloud Drive。里面是与资料库相同的「学期 / 课程 / 文件」结构，iPhone、iPad 的「文件」App 和 Mac 的访达都可以直接浏览；另有一个隐藏文件夹存放历史数据。 |
| **工作区**（Changes） | 列出未提交改动的界面，对应 GitButler 的 Unstaged 区域。 |
| **提交**（Commit） | 把勾选的改动在本机记成一条**记录**，并自动生成说明。你最初说的「点 Push 在本地仓库生成记录」就是这一步；改叫「提交」，是因为在 Git 里 Push 指上传到远程。 |
| **同步**（Sync） | 先拉取云端仓库里的新记录，再把本机未同步的记录推送上去。历史只有一条线，没有分支。 |
| **历史**（History） | 所有记录和操作的时间线，参考 GitButler 的 Operations history。 |
| **完整版本管理**（Full versions） | 适用于文本类文件（Markdown、代码、txt、LaTeX 等）和 Word（`.docx`）：保存每一个版本，可以对比差异、恢复旧版本。 |
| **仅记录变动**（Latest copy only） | 适用于其他文件（图片、PDF、PPT、Excel、音视频、压缩包等）：只记录新增、删除、修改、移动 / 重命名，**不保存旧版本**。 |

## 5. 第一版功能

### 5.1 资料库：浏览与整理

- 新建、重命名、归档学期和课程；设置课程的颜色、缩写和课程编号。缩写默认取课程名的前三个字母（例如 `Calculus of Several Variables` → `Cal`），可以自己改；色块小于 20 px 时只显示颜色。课程编号可以不填，不填时只显示课程名。归档的学期收进学期切换菜单，文件不动。
- **导入**：把文件拖进窗口或点「添加文件」，默认**复制**到当前课程，导入时可以直接打标签；可选「导入后删除原文件」。
- **接管已有文件夹**：首次使用时，把已经按学期 / 课程整理好的文件夹直接纳入管理，不移动文件。
- 重命名、移动（在课程之间拖放）、删除（进回收站）、批量打标签。
- 列表视图和网格（缩略图）视图；按名称、修改时间、大小、类型排序。
- 资料库树的上方是一排标签筛选（可多选）。例如选 `Homework`，树里只留下本学期所有作业，所在的课程和文件夹自动展开。
- 快捷视图：`最近添加`、`未打标签`。
- 在资源管理器或其他软件里对资料库做的改动（新建、保存、删除），Folio 会自动发现。
- 自动忽略系统和临时文件（`.DS_Store`、`Thumbs.db`、Office 的 `~$` 临时文件等），以及代码项目里的 `.git`、`node_modules`、虚拟环境等目录；同时遵守项目里的 `.gitignore`。忽略规则可以在设置里改。

### 5.2 快速搜索

- 全局快捷键 `Ctrl+K` 打开搜索框：输入即出结果，方向键选择，回车预览。
- 第一版搜索范围：文件名、路径、课程、标签，以及文本类文件和 Word 的正文。
- 后续版本：PDF、PPT、Excel 里的文字。扫描件的文字识别（OCR）不在计划内。

### 5.3 应用内预览

| 类型 | 预览方式 |
|---|---|
| 图片 | 缩放、适应窗口；iPhone 的 HEIC 照片在 Windows 上的支持需要验证 |
| PDF | 翻页、缩放、页内搜索 |
| Markdown | 渲染显示，支持数学公式和代码高亮 |
| 代码 / 纯文本 | 语法高亮、行号 |
| Word / Excel / PPT | 应用内直接渲染，**不依赖外部软件**。Word 连续显示、不分页，图表和 SmartArt 可能缺失；Excel 只显示数据和数字格式，不显示颜色、边框等样式；PPT 的版式可能与 PowerPoint 有偏差（效果以技术验证为准，见 ADR-0001）。随时可以「用默认程序打开」 |
| 音频 / 视频 | 系统支持的格式直接播放 |
| 其他 | 显示图标、大小、修改时间，并提供「用默认程序打开」 |

- 预览区上方显示文件名、标签（可直接增删）和操作：用默认程序打开、在资源管理器中显示、查看这个文件的历史。
- 第一版**只预览、不编辑**：双击用系统默认程序打开编辑，保存后 Folio 自动发现改动。

### 5.4 工作区：未提交的更改 → 提交

1. Folio 持续发现资料库里的改动，列在「未提交的更改」里：新增、修改、删除、重命名 / 移动。标签、课程设置的改动也算。
2. 列表默认平铺，每行开头用灰色路径标明所属课程和文件夹（例如 `MAT232/Problem sets/`），也可以切换成按课程分组。每项默认勾选；取消勾选的改动留到下次提交。
3. 点某一项：文本类和 Word 在右侧显示与上一版的差异（Word 只对比文字，不对比格式）；其他类型显示当前预览，并标明「已修改（旧版本不保存）」。
4. 提交框分标题和说明两栏，都可以不填。都留空时点 `Commit`（提交），Folio 自动生成：配置了 DeepSeek 就由 AI 撰写，否则按模板生成（例如 `MAT232: add 2 files; CSC207: update 1 file`）。也可以自己写。快捷键 `Ctrl+Enter`。
5. 提交后，记录出现在「待同步」列表里；同步之前可以修改说明，也可以撤销提交（改动回到未提交状态）。

### 5.5 同步：云端仓库

- **创建**：「创建云端仓库」，选择 iCloud Drive 里的一个空文件夹。
- **加入**：换电脑或重装系统后，「从云端仓库加入」，选择本机资料库的位置，Folio 下载全部文件和历史。
- **工具栏状态**（参考 GitButler 顶栏的 `origin/main · 5 min ago`）：例如 `iCloud | 5 min ago`，已是最新时显示 `Up to date`；有待推送的记录或云端有新记录时显示数量，例如 `↑ 2 to push`、`↓ 3 new`。
- **点「同步」**：先拉取云端的新记录并应用到本机，再推送本机的记录。Folio 会自动发现云端的新记录并提示，但只有点「同步」时才改动本机文件。未提交的改动保持不动。
- **冲突**（本机和云端在同步前都改了同一个文件，例如在 iPad 上改过、本机也改过）：
  - 文本类：能自动合并就合并；合并不了，让你选「保留本机 / 保留云端 / 两份都留」。
  - Word：不自动合并，直接让你选上面三种方式。
  - 其他文件：两份都留，例如 `作业2.pdf` 和 `作业2（云端）.pdf`。
- **在 iPhone、iPad 或 Mac 上直接改了云端仓库里的文件**：下次同步时 Folio 会发现，作为一条「来自云端的改动」拉取到本机。
- **安全**：同步带来的删除一律放进回收站；同步前自动在本机留快照，同步中断可以恢复。
- **节省空间**：本机资料库和 iCloud 里的云端仓库是两份文件。推送完成后，Folio 可以把云端仓库里的文件设为「仅在云端」来释放本机空间（需要实测）。
- 云端仓库也可以放在 OneDrive、Dropbox 等同步文件夹里；第一版以 iCloud 为主测试。

### 5.6 历史（Operations History）

- 参考截图 [`references/gitbutler-operations-history.png`](references/gitbutler-operations-history.png)：
  - 左侧是按日期分组的时间线。每条显示时间、操作图标、说明、短 ID 和**来源**（这台电脑显示设备名，例如 `G16`；在其他设备上直接改的显示 `iCloud`）。
  - 每条下面是文件卡片：类型图标、灰色路径 + 加粗文件名、右侧状态图标；超过 4 个文件时折叠为「显示全部 N 个文件」。
  - 右侧是预览区；没选文件时显示点状网格背景和「选择一个文件以预览」。
- 记录类型：提交、同步（推送 / 拉取）、来自云端的改动、修改说明、撤销提交、恢复版本、解决冲突。
- 点文件：文本类和 Word 显示这一版的内容和差异；其他文件显示变动信息（新增 / 删除 / 修改 / 移动、大小变化）。
- 文本类和 Word 可以「恢复到此版本」：恢复会产生一条新的改动，不改写历史。
- 在资料库里选中文件，可以查看这一个文件的全部历史。
- **不支持**把整个资料库回滚到某个时间点：图片、PDF 等文件不保存旧版本，整体回滚做不到完整。

### 5.7 AI 提交说明（DeepSeek，可选）

- 在设置里填入 API Key 即启用。默认 DeepSeek，也兼容其他 OpenAI 格式的服务。
- API Key 保存在 Windows 凭据管理器，不写进资料库，也不会同步到云端。
- 发送内容：文件名、改动类型、所属课程和标签，以及文本类和 Word 的改动部分（有长度上限）。PDF、图片等文件的内容不发送。设置里可以关掉「发送改动内容」。
- 说明的语言跟随界面，第一版用英文：一行摘要，以课程编号开头（没有编号时用课程名），例如 `MAT232: add lecture 5 slides`；必要时附几条细节。
- 没联网、没配置或请求失败时，自动退回模板说明，不影响提交。

### 5.8 设置

分成两个弹窗（参考 GitButler 的 Project settings 和 Global settings）：

- 方块栏底部的齿轮打开 **Library settings**：资料库位置、学期、云端仓库位置和同步选项、课程（颜色、缩写、课程编号）、标签管理、文件类型规则（哪些扩展名完整管理版本；超过 10 MB 的文本文件按「仅记录变动」处理）、忽略规则。
- 头像打开 **App settings**：本机设备名、开机启动、外观（跟随系统 / 浅色 / 深色）、减少动态效果、AI 设置、快捷键、检查更新。

## 6. 界面结构

### 6.1 视觉方向

参考 GitButler：浅暖灰底色，白色面板配细描边和圆角，强调色克制；时间、ID 等辅助信息用小号灰色字；空状态用点状网格背景。一屏只做一件事，不堆功能。设计阶段定下的方向：暖灰底色配青绿强调色，浅色和深色两套；课程、标签和文件类型共用一套 10 色的莫兰迪色板。具体数值见 `design/tokens/`，界面规格见 `docs/design/handoff/app-shell.md`。

### 6.2 整体布局

- **标题栏**：左侧应用图标和 `Folio`，右侧 Windows 窗口按钮。没有菜单栏：常用命令放在各自的位置，例如添加文件在资料库面板头，课程、标签在设置里（见设计交接文档）。
- **工具栏**（标题栏下面）：左侧云端状态、待推送 / 新记录数量和 `Sync` 按钮；中间切换当前学期（类似 GitButler 的项目切换）；右侧搜索入口（`Ctrl+K`）。
- **左侧方块栏（切换功能）**：从上到下 `Library`（资料库）、`Changes`（工作区，有未提交的改动时显示数量角标）、`History`（历史）；底部是齿轮和头像，分别打开 Library settings 和 App settings（见 §5.8）。以后的新功能也以方块的形式加在这里。
- **内容区**：随所选功能变化，见下面三张线框图。
- **窄窗口**（宽度小于 760 px）：标题栏和工具栏合成一条，列表占满宽度；打开文件后预览盖住列表，用 `Back` 返回。

线框图只表示区域划分，不代表最终样式；尺寸、颜色和界面文字以设计交接文档 [`docs/design/handoff/app-shell.md`](../design/handoff/app-shell.md) 为准。图里的英文和第一版界面一致，含义见每张图下方的说明。

```text
+----+----------------------------+------------------------------------------------+
|[Lb]| Library 25     [List|Tree] | . . . . . . . . . . . . . . . . . . . . . . .  |
|[Ch]| (All)(Notes)(Slides)(...)  | . . . . . . . . . . . . . . . . . . . . . . .  |
|[Hi]| Recently added             | . . . . . . . . . . . . . . . . . . . . . . .  |
|    | Untagged                   | . . . . . . . . . . . . . . . . . . . . . . .  |
|    | v [Cal] MAT232 Calculus... | . . . . . . . . . . . . . . . . . . . . . . .  |
|    |   v Problem sets           |              [desk illustration]               |
|    |       ps2.pdf            o |            Select a file to preview            |
|    |     Midterm review.md   oo | . . . . . . . . . . . . . . . . . . . . . . .  |
|    | > [Sof] CSC207 Software... | . . . . . . . . . . . . . . . . . . . . . . .  |
|    | > [The] CSC236 Theory...   | . . . . . . . . . . . . . . . . . . . . . . .  |
|[St]|                            | . . . . . . . . . . . . . . . . . . . . . . .  |
|(G) |                            | . . . . . . . . . . . . . . . . . . . . . . .  |
+----+----------------------------+------------------------------------------------+
```

- `[F]`：应用图标；`[-] [ ] [x]`：Windows 的最小化、最大化、关闭按钮。标题栏下面一行是工具栏。
- `^2 v1`：有 2 条记录待推送、云端有 1 条新记录（界面上显示为 `↑ 2 to push`、`↓ 1 new`）；`[Sync]` 即「同步」。
- `[Lb] [Ch] [Hi]`：方块栏——资料库、工作区、历史。`[St]` 是齿轮，`(G)` 是头像（取本机设备名 `G16` 的首字母）。
- 第二栏：一棵树，课程 → 文件夹 → 文件，上方是标签筛选。`[Cal]` 是课程色块（颜色 + 课程名前三个字母），后面先是加粗的课程编号 `MAT232`，再是灰色的课程名；`o` 是文件的标签色点。
- 第三栏：预览区。没选文件时显示点状网格和「书桌一角」插画；选中课程或文件夹时显示其中文件的网格。

**工作区（Changes）**（标题栏和工具栏同上）

```text
+----+--------------------------+-----------------------+--------------------------+
|[Lb]| Changes 4   [List|Tree]  | [Summary (optional) ] | MAT232/review.md   [/]   |
|[Ch]|--------------------------| [Description ...    ] | [Changes|This version]   |
|[Hi]| [x] MAT232/lec5.pptx [+] | [Generate v]          |--------------------------|
|    | [x] MAT232/review.md [/] | [Commit 4 changes   ] |  8   8   ## Gradients    |
|    | [x] CSC207/notes.md  [/] |-----------------------|  9     - old line        |
|    | [x] ECO101/old.pdf   [-] | Not synced 2          |      9 + new line        |
|    | [ ] MAT232/ex14.jpg  [>] | o Your commit here    | 10  10   same line       |
|    |                          | o MAT232: add lec 5   |                          |
|    |                          | o CSC207: update...   |                          |
|[St]|                          | [Sync now]            |                          |
|(G) |                          |                       |                          |
+----+--------------------------+-----------------------+--------------------------+
```

- 第二栏：未提交的改动，默认平铺，每行开头的灰色路径标明课程和文件夹，也可以切换成按课程分组。`[x]` 表示这次提交包含该项。
- `[+] [/] [-] [>]`：新增 / 修改 / 删除 / 重命名或移动。界面上是描边小方块里的符号（和 GitButler 一样），不用文字。
- 第三栏：提交框，标题和说明都可以留空，留空时自动生成；`Commit` 即「提交」。下面的 `Not synced` 是已提交、还没同步的记录，新的提交出现在 `Your commit here` 的位置。
- 第四栏：文本类和 Word 显示与上一版的差异，其他文件显示预览和改动说明。

## 7. 关键流程

1. **首次使用**：欢迎页 → 新建资料库，或接管已有文件夹 → 建第一个学期和课程 →（可选）创建云端仓库 →（可选）填 DeepSeek API Key。
2. **换电脑或重装后**：从云端仓库加入 → 选本机位置 → 下载完成即可使用。
3. **日常**：下载课件 → 拖进 Folio 当前课程 → 打 `Slides` 标签 → 工作区出现改动 → 提交 → 同步。
4. **在 iPad 上改了文件**：回到电脑，顶栏提示「云端有新改动」→ 同步 → 改动出现在资料库和历史里。
5. **找回旧版笔记**：历史 → 找到那次提交 → 点文件看差异 → 恢复到此版本 → 提交。
6. **处理冲突**：同步时提示冲突 → 逐个选择保留方式 → 完成同步。
7. **新学期**：新建学期 → 批量建课程 → 归档上学期。

## 8. 第一版不做

- macOS 版（以后需要时用 Swift 单独开发）。
- 分支、多人协作、共享资料库。
- 手机 / 平板 App（可以用 iOS「文件」App 浏览云端仓库）。
- 在 Folio 里编辑文件内容（例如 Markdown 编辑器）。
- 图片、PDF、PPT、Excel 等文件的旧版本保存与恢复；整个资料库回滚。
- PDF、PPT、Excel 的全文搜索（放到后续版本）；OCR。
- 自建服务器，或同步文件夹以外的云服务。
- 按规则自动打标签（后续版本候选）。

## 9. 质量要求

| 方面 | 要求 |
|---|---|
| 数据安全 | Folio 的任何操作都不能让文件无声丢失：删除进回收站，同步前留快照，同步中断可恢复。标签等元数据用可读的文本格式保存在资料库里。 |
| 性能目标 | 5 万个文件、100 GB 的资料库依然流畅；输入后约 0.2 秒内出搜索结果；常见文件 1 秒内出现预览。（在 ADR 中验证） |
| 离线 | 没有网络或 iCloud 还没同步完时，本机功能照常，同步稍后进行即可。 |
| 平台 | 只支持 Windows 10 / 11；快捷键按 Windows 习惯；从 iPad、Mac 放进云端仓库的文件名如果在 Windows 上不合法，要明确提示。 |
| 隐私 | 除你开启的 DeepSeek 和检查更新外不联网；不收集使用统计。 |
| 无障碍 | 对比度达到 WCAG 2.1 AA；可以完全用键盘操作；焦点清晰可见；尊重系统的「减少动态效果」设置。 |
| 分发 | Windows 安装包；应用内自动更新；给同学朋友的安装说明（包括没有代码签名时，如何在 SmartScreen 提示中放行）。 |

## 10. 第一版的成功标准

- 新学期开始，5 分钟内建好全部课程并导入已有文件。
- 任何文件都能在 3 秒内搜到并预览。
- 连续使用一整个学期：资料库和云端仓库之间没有文件丢失或损坏，每次冲突都有明确的提示和选择。
- 日常「提交 + 同步」只需要点两下。

## 12. 对技术方案的影响（供 ADR 使用）

- **ADR-0001 技术栈**：只做 Windows（2026-09-26 决定），不需要考虑跨平台一致性。需要可靠地监控上万个文件；在应用内渲染 PDF、Word、Excel、PPT、Markdown 和代码；调用回收站和 Windows 凭据管理器；没有付费代码签名时的应用内自动更新；Playwright 端到端测试。如果以后用 Swift 开发 Mac 版，最好能复用核心逻辑，至少要能读写同一个云端仓库。
- **ADR-0002 数据存储**：分两类数据。
  - 随资料库同步的数据（标签、课程设置、提交记录）：必须放在资料库和云端仓库里，可合并、可读。
  - 只属于本机的数据（搜索索引、缩略图、预览缓存）：放在应用数据目录，丢了可以重建。
  - 课程设置新增可选的课程编号（例如 `MAT232`），需要补进 ADR-0002 和 `docs/specs/library-core.md`（2026-09-27）。
- **ADR-0003 版本记录与同步格式（新增）**：本产品最关键、最难回退的决定。约束如下：
  1. iCloud 没有文件锁，而且是最终一致的：多个设备（多台电脑，或电脑和 iPad）改写云端里的同一个文件时，iCloud 会生成「xxx 2」这样的冲突副本。云端的历史数据应该只新增、不修改（例如按内容哈希命名的文件，加上每台设备各自追加的记录）。
  2. 云端的文件区保持普通文件夹结构，并能识别 iPad 等设备直接做的修改。
  3. 文本类和 Word 保存全部版本；其他文件只保存当前版本。
  4. 本机离线时的提交和云端的新改动（来自其他电脑或 iPad）在同步时要能排成一条线；改到同一个文件时交给用户决定。
  5. 是否直接使用 Git：Git 仓库放在 iCloud 中有已知的损坏风险，因此云端倾向自定义格式；本机是否用 Git 保存文本版本，在 ADR 中比较。
  6. iCloud「仅在云端」的占位文件：读取时要等待下载完成；推送后把文件设为「仅在云端」来释放空间，需要在 iCloud for Windows 上实测。
  7. 文件名：从 iPad、Mac 放进云端仓库的文件名可能在 Windows 上不合法（`: * ? " < > |`、保留名、路径长度限制、Unicode 规范化差异）。
  8. 云端仓库的格式要写成文档、与编程语言无关，以后的 Swift 版 Mac 应用也能读写。
- **预览**：不依赖外部软件的 Office 渲染需要先做技术验证（重点看 PPT）；HEIC 图片在 Windows 上的预览需要验证。
- **搜索**：中文不分词，需要支持子串匹配；需要从 Word 中抽取文字。
- **DeepSeek**：请求只从特权层发出；API Key 存在系统凭据库；改动内容设长度上限。这是新增的联网能力，需要做 `/security-review`。

## 13. 已采用的默认设定（可以改）

以下几项没有单独询问，先按常见做法定下。看到不合适的直接告诉我：

| 项 | 默认做法 |
|---|---|
| 按钮命名 | `Commit`（提交）生成本机记录，`Sync`（同步）= 拉取 + 推送 |
| 导入 | 复制到当前课程；可选导入后删除原文件 |
| 删除 | 进回收站；同步带来的删除也一样 |
| 编辑 | 第一版只预览；双击用系统默认程序打开编辑 |
| 标签位置 | 资料库树上方的筛选条；预设 `Notes` `Slides` `Homework` `Exams` `Reference` |
| 拉取时机 | 自动发现云端新记录并提示；点「同步」才改动本机文件 |
| 冲突 | 文本类尝试自动合并，否则由你选；Word 由你选；其他文件两份都留 |
| 大文件 | 超过 10 MB 的文本文件按「仅记录变动」处理 |
| Excel | 仅记录变动（不保存旧版本） |
| 资料库数量 | 每台电脑一个资料库（数据结构预留多个） |
| 外观 | 跟随系统浅色 / 深色，可手动切换 |
